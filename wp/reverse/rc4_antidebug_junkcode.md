# Reverse2 - RC4魔改与反调试

## 来源
CTF比赛: 2026年广东省大学生计算机设计大赛"网络与数据安全挑战赛"决赛
年份: 2026

## 类型
Reverse - RC4魔改 / 反调试 / 花指令 / 真随机数

## 题目分析
题目使用RC4加密算法，但存在以下难点：花指令混淆、TLS反调试、RC4算法魔改（xor改为+=）、真随机数影响密钥生成。需要在绕过反调试的同时，分析魔改RC4算法并处理真随机数问题。

## 解题思路
1. 信息收集
   - 在TLS回调中发现反调试代码，调试状态下密钥会被替换为"xixixx"
   - 存在大量花指令：`xor eax, eax; jz +2`
   - 存在类似canary的堆栈保护，错误patch会导致堆栈不平衡
   - 主函数中校验flag长度、flag头（DASCTF）和密文

2. 漏洞分析
   - 反调试：TLS中检测调试器，修改密钥
   - canary保护：改`cmp eax, 0`绕过，而非直接patch
   - RC4魔改：PRGA阶段将xor改为+=，同时异或`dword_E5A1B0[i % 6]`
   - 真随机数：系统调用真随机数影响`dword_E5A1B0`数组的生成
   - KSA阶段未魔改

3. 漏洞利用
   - 先用已知明文"DASCTF"（flag头6字节）与密文相减，再异或KSA的keystream，反推出`dword_E5A1B0`数组
   - 获取`dword_E5A1B0`后，用标准RC4 KSA + 魔改PRGA解密完整密文

4. Flag获取
   - 编写C解密脚本，利用已知明文反推密钥依赖数组，再解密完整密文

## 使用工具
- IDA Pro
- C/C++ 编译器（用于编写解密脚本）

## Payload
```c
// 核心解密逻辑
// 1. 用KSA生成keystream
// 2. 已知明文"DASCTF"与密文相减，异或keystream反推dword_E5A1B0
// 3. 用完整dword_E5A1B0 + 魔改RC4解密

// 魔改点：PRGA中 xor 改为 +=，同时异或 dword_E5A1B0[i % 6]
Str[i] -= LOBYTE(dword_E5A1B0[i % 6]) ^ a3[(a3[v5] + a3[v6]) % 256];

// 密文数组
v9 = {13, -41, -5, 5, -32, -18, 13, -105, -92, -17, 96, 20, -29, -96, 41, -117, 74, 55, -20, 83, -66, -48, -46, -8, -83, 19, 96, -89, -58, -60, 96, 113, -43, 85, 113, 19, 62, -1, 29, -6, 18, -128, -29, 41};
```

## Flag获取方式
利用已知明文"DASCTF"反推魔改RC4的密钥依赖数组，再解密完整密文得到flag。

## 技术总结
关键词：RC4魔改, 反调试, TLS回调, 花指令, 真随机数, canary保护, 已知明文攻击

核心要点：
1. TLS回调中常放置反调试代码，直接搜索TLS可快速定位
2. 花指令`xor eax, eax; jz +2`是常见混淆手段
3. canary类保护改`cmp eax, 0`即可绕过，不要直接patch堆栈操作
4. 已知明文攻击：利用flag头反推密钥依赖值
5. RC4魔改常见于PRGA阶段，KSA通常保持不变
6. 真随机数导致模拟执行无效，需要静态分析算法逻辑
